# AI 释义与闪卡：验证记录

日期：2026-10-27。本次在 `Documents/ChatGPT/外刊闪卡/outputs/inkword` 继续开发；旧源码保留不动，预览沿用 `http://127.0.0.1:3000`，兼容同源浏览器记录。

## 实现范围

OpenAI Responses 结构化解释、词组/单词不同提示、原文与 AI 例句区分、确认后的逐条批量生成、部分结果保存与缺失重试、停止后续请求、闪卡翻面与三档反馈。API Key 仅后端环境读取；无密钥则提示配置。未增加账号、Supabase、FSRS 或真实词典服务。

## 验证边界

**本机没有 OPENAI_API_KEY，未进行真实 OpenAI 联调、计费或输出质量评估。**

后端通过官方 SDK 加 HTTP MockTransport 验证请求/解析合约，浏览器在隔离测试会话中拦截 AI 请求返回测试夹具。截图如含生成释义，会标明测试数据，不代表真实模型结果。产品本身没有模拟供应商或假数据回退。

- 原 17 项 PDF/API 测试继续回归，包括用户 WPS 文件 9 个高亮。

## 独立审查

审查发现 AI 返回时整篇旧快照可能覆盖另一页面的修改或学习反馈。已增加 `commitExplanation`：重新读取最新记录，只写目标词条 ai；检查文章确认状态、目标存在、输入签名一致。文章被删除或修改时停止当前批次并加载最新状态。单元及浏览器测试先复现失败，再验证修正。

## 实施决定

- 延续用户“直接开发”的授权，不重复设计确认。
- 使用官方 Python SDK、Pydantic strict schema，默认模型为可配置的 gpt-4.1-mini。
- 生成逐条进行，便于进度、部分成功保存和停止；停止后仍等待当前请求完成，当前请求可能已经产生费用。
- localStorage schema 维持 v1，通过可选字段扩展，避免迁移覆盖既有数据。
- 评分事件单独记录，当前不声称实现间隔重复调度。
- 为保留当前浏览器数据，预览地址与端口不变，只更换本任务服务进程。

后续真实验收须配置本机密钥，先用一个词条验证权限、模型支持和输出质量，再生成全部词条。
