## 独立审查与修正

审查发现两项重要问题，均以浏览器失败测试复现后修正：

1. 编辑页码会关联错误证据：新增不可变的 `source_page`，与可编辑 `page` 分离。
2. 上传等待时打开其他文章可能丢失编辑：上传期间禁止 `open()` 切换当前文章。

另将禁止存储时原始备份按钮的未捕获异常纳入本次修正，因它位于存储失败后的恢复流程；测试先观察到 `Access denied`，修正后应返回可见提示。

## 实施选择与限制

- 用户明确授权直接开发；按其技术栈在本地新目录实施，没有新建托管站点或发布云端服务。原因是本阶段必须真实运行 Python/PyMuPDF；代价是需要本机前后端同时运行。
- 项目起始无 Git 仓库，未创建共享分支、提交或 worktree。源码完整交付，可后续初始化 Git。
- Turbopack 在本机子进程通信失败；改用 Next.js webpack 后生产构建通过。功能不受影响，但以后可重新评估构建工具。
- 首次沙箱 API 测试卡在 Windows asyncio socketpair；允许本机通信后同一套测试通过，未绕过产品错误处理。
- 真实 WPS 样本只有单行单词和词组。跨行、双栏等为合成样本，不能据此声称所有 WPS 版本及复杂版式均兼容。
- 无文字层用空白页作为受控测试；尚未收集真实扫描文档和 OCR 错字样本。
- 上下文算法为启发式；跨页、不规则分栏、连字、特殊缩写和断词仍可能需要人工确认。
- 存储仅在当前浏览器/来源域内，JSON 当前只能导出，没有导入 UI。
- 有一条第三方 Starlette 测试客户端对 httpx 的弃用警告，不影响 17 项测试结果；后续依赖升级可迁移 httpx2。
- Playwright 在执行环境显示 NO_COLOR/FORCE_COLOR 配置警告，不影响测试。

AI 解释、结构化 OpenAI 输出、词典释义与闪卡没有在这次实现，属于下一阶段。
